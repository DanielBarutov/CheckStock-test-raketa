# CheckStock 📦

**CheckStock** — прототип системы складского учёта для одного магазина.

Приложение позволяет отслеживать остатки товаров, создавать резервы FBS, перемещать товары между складами, управлять поставками FBO и просматривать историю операций.


## Ключевые решения

- **Один сервис и одна база.** FastAPI обрабатывает формы и отдаёт страницы Jinja2, а PostgreSQL хранит остатки, отправки и журнал. Для одного магазина этого достаточно. Страница читает данные из одного снимка PostgreSQL, поэтому таблица остатков и история согласованы даже во время параллельной операции.
- **Физический остаток, резерв и товар в пути учитываются отдельно.** Доступный остаток на активном складе равен физическому за вычетом резерва. Резерв FBS уменьшает доступное количество, а отправка клиенту уменьшает и физический остаток, и резерв. При перемещении товар списывается с исходного склада при отправке и зачисляется на склад назначения при приёмке. Приёмка FBO переводит уже списанный товар из статуса «В пути» в «Принято».
- **Операция проводится целиком.** SQLAlchemy открывает транзакцию и блокирует строку магазина через `with_for_update()`. Пока одна команда проверяет остаток и записывает изменения, следующая команда ждёт. Остатки, статус, журнал и результат по ключу запроса сохраняются вместе. Повтор с тем же ключом получает прежний результат, а повторная приёмка с новым ключом проверяет статус отправки.
- **Решение о нехватке остаётся за менеджером.** Если выбранного склада недостаточно, CheckStock показывает доступное количество на нём и остатки на других активных складах. Менеджер может выбрать другой склад или провести перемещение.
- **Удаление склада сделано через архивирование.** У склада сохраняются идентификатор, физический остаток и история. Архивный склад исключается из новых операций, при этом ранее отправленные перемещения и открытые резервы можно завершить.
- **Правила учёта отделены от доступа к базе.** `domain` определяет доступность, изменения остатков и переходы статусов. `application` выполняет сценарии через порты `typing.Protocol`, а репозитории `infrastructure` сохраняют данные через SQLAlchemy ORM. HTTP-обработчики получают порты через FastAPI `Depends`.

## 🚀 Быстрый запуск

Выберите свою операционную систему и выполните команды из соответствующего раздела.

### 🪟 Windows (WSL2)

**Шаг 1. Подготовка окружения**

Установите [Docker Desktop](https://www.docker.com/products/docker-desktop/) и включите интеграцию с WSL2 в настройках Docker Desktop.

Если WSL2 ещё не установлен, откройте PowerShell от имени администратора:

```powershell
wsl --install -d Ubuntu
```

После установки откройте терминал Ubuntu (WSL2).

Установите необходимые утилиты:

```bash
sudo apt update
sudo apt install -y make curl
```

Убедитесь, что Docker доступен:

```bash
docker compose version
```

**Шаг 2. Запуск приложения**

Перейдите в корневую директорию проекта, содержащую `Makefile`.

Запустите контейнеры:

```bash
make up
```

Дождитесь готовности приложения:

```bash
curl -fsS --retry 12 --retry-delay 1 --retry-all-errors http://127.0.0.1:8000/health
```

**Шаг 3. Загрузка тестовых данных**

```bash
make seed
```

**Шаг 4. Открытие приложения**

Откройте в браузере Windows:

http://127.0.0.1:8000/

**Шаг 5. Остановка приложения**

```bash
make down
```

Все команды `make` выполняются в терминале Ubuntu (WSL2), а не в PowerShell.

## 📦 Демонстрационные данные (Seed)

После выполнения `make seed` система создаст:

- 2 склада: **Север** и **Юг**
- 3 товара (SKU)
- 4 операции поступления товаров

**Важно:** команду `make seed` можно выполнять повторно. Дублирования остатков не произойдёт.

## 🖥️ Интерфейс приложения

После запуска откройте:

**http://127.0.0.1:8000/**

На главной странице вы увидите:

- **Физический остаток** — фактическое количество товаров на складе, включая зарезервированные.
- **Доступно** — количество товаров, которое можно зарезервировать.
- **Резерв FBS** — товары, зарезервированные под заказы.

Через меню доступны отдельные страницы:

- Складские операции
- Перемещения
- Заказы FBS
- Поставки FBO
- История операций

## 🧪 Как проверить работу

После выполнения `make seed` можно пройти небольшой сценарий.

### 1. Попробуйте зарезервировать товар

Создайте резерв FBS:

- Товар: `SKU-101`
- Склад: `Юг`
- Количество: `7`

Приложение покажет, что доступного остатка недостаточно.

На складе **Юг** доступно 6 единиц, а на складе **Север** — 10.

### 2. Переместите товар

В разделе «Перемещения» заполните форму отправки:

- Откуда: `Север`
- Куда: `Юг`
- Товар: `SKU-101`
- Количество: `2`

Нажмите «Отправить». Когда товар появится в списке перемещений, нажмите «Принять».

### 3. Повторите резерв

Теперь на складе Юг станет доступно 8 единиц товара `SKU-101`.

Повторите создание резерва на 7 единиц. Операция должна успешно выполниться.

### 4. Проверьте историю

Откройте раздел истории операций, чтобы посмотреть выполненные действия.
