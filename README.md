# CheckStock

Прототип складского учёта для одного магазина. Главная страница показывает физический остаток, доступное количество, резерв FBS, товар в пути и историю операций. Складские команды выполняются через формы на той же странице.

## Запуск

Нужны Docker с Compose и Make. Запускайте команды из корня репозитория.

```sh
make up
curl -fsS --retry 12 --retry-delay 1 --retry-all-errors http://127.0.0.1:8000/health
make seed
```

Откройте `http://127.0.0.1:8000/`. Миграция применяется при старте. `make seed` создаёт склады «Север» и «Юг», три SKU и четыре прихода. Повторная загрузка не удваивает остатки. `make down` останавливает контейнеры и сохраняет данные. Для отдельного прогона на чистой базе задайте новое имя через `COMPOSE_PROJECT_NAME` во всех командах запуска. Порт можно изменить через `CHECKSTOCK_PORT`.

## Проверка

Для тестов нужны Python 3.13, uv и Docker. Интеграционные тесты запускают PostgreSQL 18 во временном контейнере с отдельной базой для каждого сценария.

- `make test` проверяет поведение через FastAPI и реальные транзакции PostgreSQL. Порог покрытия строк и ветвей в совокупности — 95%.
- `make check` добавляет Ruff и mypy.
- В демо попробуйте зарезервировать 7 единиц SKU-101 на Юге. Система покажет 6 доступных на Юге и 10 на Севере. Отправьте и примите 2 единицы с Севера на Юг, затем повторите резерв.

## Решения

- FastAPI принимает команды и отдаёт серверные шаблоны Jinja2. Сценарии приложения используют порты на `typing.Protocol`, PostgreSQL подключён через SQLAlchemy Core и psycopg.
- Физический остаток включает резерв. Резерв уменьшает доступное количество, отправка FBS уменьшает физический остаток и резерв. Перемещение и FBO списывают товар с ФФ при отправке. Приёмка перемещения добавляет товар получателю, а приёмка FBO меняет статус поставки.
- Каждая команда блокирует строку магазина и записывает изменения, историю и результат по ключу запроса в одной транзакции. Повтор с тем же ключом возвращает записанный результат. Подтверждения проверяют состояние операции и защищены также при повторе с новым ключом.
- Архивный склад остаётся виден с физическим остатком и историей. Новые операции выбирают активные склады. Ранее отправленное перемещение и открытый резерв можно завершить после архивации.
- Остатки, статусы отправок и история читаются из одного снимка PostgreSQL. Модель рассчитана на локальную демонстрацию с одним магазином и ручными операциями FBS/FBO. Стили загружаются через CDN.
